# OutBot's Coding Standards

- Use 4 spaces
- Use consistent and descriptive names for your variables, functions, parameters, classes, and files/directories
- Use DRY where appropriate
- Use Google style docstrings for all your functions and methods but **NOT** your classes
- Use normal docstrings for classes and make sure docstrings (for classes) are under 100 characters
- Try not to use emojis
- Try to write **SIMPLE** code, rather than **CLEVER** code
- Avoid nesting where possible
- You may use Ai but make sure you proofread all the code Ai gives you
- Before submitting your code, please run your code through ruff, codespell, pyright, and tests
- Please read and listen to comments
- Update anything that may be out of date, inaccurate, and/or cause OutBot to not function properly
- Try **NOT** to collect any user data if possible
- Use double quotes instead of single quotes
- Use type hints as much possible
- Documentation should be easy to follow and get to the point quickly

# Pull Requests

1) Fork/clone the repository
2) Create a branch for your changes
3) Run through ruff, codespell, pyright, and tests
4) Proofread your changes
5) Open a pull request explaining:  
    - What did you change?  
    - Why you changed what you changed?  
    - What benefits OutBot will gain?  
    - Will this help users have a better experience with OutBot?  
    - Ai use  
    - How you would like to be credited

# Developer Notes

If unsure if something follows OutBot's coding standards, you may ask in your pull request. Try to follow OutBot's coding standards to the best of your ability. Thank **you** for contributing to OutBot.
